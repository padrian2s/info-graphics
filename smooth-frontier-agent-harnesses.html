The 5 stories that matter

Click to expand · skim fast
1
The jagged frontier was never about AI intelligence — it was an artifact of how we asked Single-turn, no-notes, no-retries = asking a brilliant analyst to solve everything in 30 seconds
▾

We deployed AI into a paradigm that stripped away every organizational structure humans use to think — review processes, sprint cycles, peer feedback, draft-revise-publish pipelines — then described the resulting failures as a property of AI intelligence. But we forgot: we can't solve one-shot cognition problems well either.

Why single-turn fails

  • Errors propagate: one mistake midway corrupts everything downstream.
  • No mechanism to detect a wrong first approach and try another.
  • Can't accumulate information beyond the context window.
  • Every problem must be solved in one shot.

What actually improved

  • Inference compute: AI takes time to think, tries tokens, self-corrects.
  • Tool use: AI gets access to external capabilities.
  • Better prompting: we learned to describe tasks more clearly.
  • Two curves: intelligence and our fluency at using the tool.
Key insight: The fluency curve (our ability to use agents in harnesses) matters more than the intelligence curve for practical work right now.
2
Cursor's coding agent solved a novel math proof — without being built for math Same harness that built a web browser from scratch ran for 4 days on spectral graph theory
▾

On March 3, Cursor CEO Michael Truell announced their coding harness solved Problem 6 of the 1st Proof — a research-grade math problem from unpublished Stanford/MIT/Berkeley work. It didn't just solve it: it improved on the human solution with stronger bounds and better coverage. Zero hints. Zero human nudges. 4 days of autonomous running.

Why this matters

  • Cursor is a coding company, not a math company.
  • The same harness previously built a web browser from scratch in Rust.
  • A system designed to write code produced mathematics its authors hadn't found.
  • This suggests agent harnesses generalize beyond their original domain.

Other Cursor harness results

  • Web browser from scratch in Rust (ran for a week).
  • Solid-to-React migration.
  • Java language server.
  • Windows 7 emulator — 1.2M lines of code.
  • Excel clone — 1.6M lines of code.
Truell's insight: "Our technique for scaling agent coordination might generalize beyond coding" — to any domain that is even reasonably verifiable.
3
The harness that works: hierarchy, specialization, clean isolation Flat coordination failed — the breakthrough came from removing complexity, not adding it
▾

Cursor's first attempt was flat coordination: agents sharing a single file with locks. It failed badly — agents became risk-averse, avoided hard tasks, and optimized for small safe changes. The breakthrough came from hierarchy: planners → sub-planners → workers → judge. And counterintuitively, many improvements came from stripping out complexity rather than adding it.

Architecture that works

  • Planners explore the codebase, create tasks, spawn sub-planners recursively.
  • Workers pick up individual tasks, grind until done, ignore everything else.
  • Judge (LLM-as-judge) determines whether to continue; next iteration starts fresh.
  • Fresh context restart = most important property (solves context window limits).

Two key lessons

  • Model choice matters for long-horizon tasks: GPT-5.2 consistently outperformed Claude Opus (which tended to stop earlier and take shortcuts).
  • Removing complexity beats adding it: stripped out coordination machinery, added hierarchy, let agents work in clean isolation.
  • Prompt design disproportionately determines system behavior.
Design principle: the improvement came from simplification — hierarchy + isolation, not more elaborate coordination.
4
4 labs built the same system independently — this is not a coincidence Anthropic, Google DeepMind, OpenAI, Cursor all converged on decompose → parallelize → verify → iterate
▾

None coordinated. All four exhibit a similar structural pattern. This convergence is a solution to a fundamental problem: how do you get useful work from units of intelligence with finite context, finite per-step reliability, and no persistent memory? The answer — for both humans and agents — turns out to be organizational.

The four approaches

  • Anthropic: initializer agent + progress file + structured artifacts for next session.
  • Google DeepMind: separates generation, verification, revision into distinct roles.
  • OpenAI Codex: parallel sandbox environments with isolated execution.
  • Cursor: planner → worker → judge hierarchy (like a PM + engineers).

Why convergence matters

  • Same principles as human orgs: roles, handoffs, verification, restart procedures.
  • These are management insights that generalize to autonomous agents.
  • We figured out organizational intelligence for humans — now it scales for agents too.
  • The pattern is domain-agnostic: works for any verifiable problem class.
Deep parallel: We don't structure human orgs as "one very smart person doing everything." We use roles, handoffs, and verification. Agents need the same thing — and now they have it.
5
The skill that survives: sniff-checking, not execution Two tiers of verifiability open up most knowledge work to agent delegation
▾

If AI can tackle any problem that's decomposable and verifiable, the question shifts from "can AI do this specific task?" to "can my work be decomposed into verifiable sub-problems?" The answer is yes far more often than most of us are comfortable with. The skill that survives isn't "I can do the work" — it's "I can tell if the work is correct."

Two tiers of verifiability

  • Tier 1 — Machine-checkable: code compiles or doesn't, tests pass or fail.
  • Tier 2 — Expert-checkable with clear criteria: math proofs, engineering designs, legal briefs, product strategies.
  • Tier 2 is bigger than people think: 3-4 experienced product leaders will agree on whether a strategy is correct.
  • "Soft work" is more verifiable than we assume.

Meta-skills that matter

  • Knowing whether architecture is maintainable.
  • Recognizing a solution that is fragile.
  • Understanding when tests cover all important cases.
  • Decomposing problems into delegatable sub-tasks.
  • These get more valuable as harnesses improve, not less.
Every department: Marketing can sniff-check campaign designs. Customer success can sniff-check email schemas. The best orgs are delegating the hard stuff — not just the easy stuff.

What to do with this (one-page checklist)

Pick the row that matches you

If you're an individual contributor

  • Map your daily work: which tasks are decomposable and verifiable? Start delegating those to agents.
  • Build your sniff-check muscle — practice evaluating AI outputs rather than producing from scratch.
  • Learn to design harnesses: task files, memory structures, clear prompts with complete success criteria.
  • Think "team of one" — you + multi-agent coordination = team of a hundred.

If you lead a team or organization

  • Stop thinking "AI can do the easy stuff" — the best orgs delegate the hard stuff they can sniff-check.
  • Invest in agent infrastructure: harnesses, evaluation pipelines, and structured handoff patterns.
  • Train people on taste, decomposition, and verification — these meta-skills get more valuable as execution gets cheaper.
  • The relevant question is shifting: not "can AI do X?" but "can X be decomposed into verifiable sub-problems?"
Core message: The frontier is smooth for work. Capabilities are not jagged at work. We essentially scaled our organizational intelligence tools for people into AI — and it finally hit a tipping point.
