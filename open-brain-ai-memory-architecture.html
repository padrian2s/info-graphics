The memory problem hiding inside your prompting Every new chat = starting from zero • every platform switch = lost context
▾

The quality of AI output depends entirely on the quality of your ability to specify. But the best prompt in the world cannot compensate for an AI that doesn't know what you've been working on, what you've already tried, what your constraints are, or what you decided last Tuesday. You're burning your best thinking on context transfer instead of real work.

The walled garden trap

  • Claude's memory doesn't know what you told ChatGPT.
  • ChatGPT's memory doesn't follow you into Cursor.
  • Your phone app doesn't share context with your coding agent.
  • Five separate piles of sticky notes on five separate desks.

The lock-in strategy

  • Memory is designed as lock-in — keeps you on one platform.
  • Want to try a new model? You lose all accumulated context.
  • None of this built-in memory is agent-readable.
  • Your knowledge is a hostage to a single platform.
Person A vs Person B: Person A opens Claude, spends 4 minutes explaining their role, project, constraints. Person B opens Claude — it already knows everything via MCP. Same model, wildly different outcomes. The variable is infrastructure.

Human web tools

Agent web infrastructure

  • Build for the agent web; humans benefit downstream.
Toby Lütke's insight: "A lot of corporate politics amount to bad human context engineering." When you build clean context engineering for agents, you happen to build clean context engineering for people too.
3
Open Brain architecture: Postgres + pgvector + MCP 45-minute setup • $0.10/mo • no SaaS middlemen • no coding required
▾

Your thoughts live in a Postgres database you control. Not somebody else's proprietary format. Postgres isn't exciting. It's not deprecating. It's not VC-backed. It's boring, battle-tested, and that's exactly what you want as your foundation. Every thought gets converted into a vector embedding — a mathematical representation of meaning that is natively AI-readable.

Capture flow (<10 seconds)

  • Type a thought in Slack (or any capture point).
  • Hits a Supabase edge function.
  • Generates embedding + extracts metadata in parallel.
  • Stores both in Postgres with pgvector.
  • Replies in-thread with confirmation.

Retrieval via MCP

  • semantic_search: find thoughts by meaning.
  • list_recent: browse what you captured this week.
  • stats: see your patterns over time.
  • Works from Claude, ChatGPT, Cursor, VS Code, Claude Code — anywhere.
Semantic search example: Ask "what was I thinking about career changes last month?" — finds your note about considering consulting even if you never used the word "career" in the original thought.

Build it this weekend (checklist)

45 minutes, zero coding

Setup steps

  • Create a free Supabase project (Postgres + pgvector included).
  • Deploy the edge function for capture (embedding + metadata extraction).
  • Connect a capture point: Slack channel, messaging app, or any MCP client.
  • Install the MCP server config in Claude / Claude Code / Cursor.
  • Run the memory migration prompt to pull existing context from ChatGPT and Claude.

First week habits

  • Use quick capture templates: decisions, people notes, insights, meeting debriefs.
  • Run the Open Brain Spark interview to discover your capture patterns.
  • Test semantic search from at least 2 different AI tools to feel the difference.
  • End-of-week: run the weekly review prompt to see clusters, gaps, and unresolved items.
  • Goal: 10–20 thoughts/day. The system compounds — every input makes every future search smarter.
