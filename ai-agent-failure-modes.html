The Four Failure Modes

Applies to all agents, not just medical
01
📈

The Inverted U

Agents perform best on routine cases — exactly where performance matters least. They fail on extreme edges where stakes are highest. Your "87% accuracy" dashboard is masking silent failures on the tails.
Atypical emergenciesRoutine casesAtypical minor
Health: Classical stroke? Nails it. Atypical respiratory failure? Misses it.
Enterprise: Routine invoices? Perfect. Slightly modified duplicate? Sails through.
So what? No eval designed to measure average accuracy will surface this. You need tail-focused testing.
02
🧠

The Agent Knows but Doesn't Act

The reasoning trace correctly identifies a finding — then the output contradicts it. Chain of thought and final answer operate as semi-independent processes. Studies show models fail to update outputs from reasoning changes >50% of the time.
Reasoning Trace
"Early respiratory failure detected"
≠
Output

Compliance: Reasoning identifies enhanced due diligence jurisdiction. Output classifies as "standard risk."
Support: Analysis spots known billing error pattern. Recommends generic 5–7 day review anyway.
So what? If CoT faithfulness can't be fixed at the model level, the solution must be architectural. Compare traces to outputs externally.
03
🗣

Social Context Hijacks Judgment

When a family member said "the patient looks fine," ChatGPT Health was 12x more likely to recommend less urgent care. The structured data should drive decisions; unstructured language creates anchoring bias.
Without social cue
"Seek immediate emergency care"
With "patient looks fine"
"Monitor at home, follow up if needed"
Procurement: Senior VP note says "I'm confident this is right." Agent's analysis shifts to match, regardless of data.
Lending: Employer letter calls applicant "valued longtime employee." Risk score shifts without material financial info.
So what? Without controlled A/B testing (same scenario +/- anchoring cue), this bias is invisible on standard evals.
04
🚨

Guardrails Fire on Vibes, Not Risk

The crisis intervention system activated more for vague emotional distress than concrete self-harm threats. Mount Sinai's chief AI officer: "The alerts were inverted relative to clinical risk." Guardrails match surface language, not actual risk taxonomies.
Triggers alert (low risk)
"I've been feeling so hopeless lately..."
Misses alert (high risk)
"I have a plan to end things tonight"
Security: Flags email labeled "Confidential Financial Data" (a public press release). Misses 50K customer records exported to personal Dropbox described as "project backup."
So what? The system will tell you it's doing well. You have to know enough to say "actually, that's wrong and here's why." Test for real safety, not the appearance of safety.

The Key Methodology — Factorial Design: Mount Sinai tested the same scenario across 16 contextual variations, systematically adding stressors (social cues, time pressure, hedging qualifiers, contradictory context). This controlled variation exposed anchoring bias, guardrail inversion, and the inverted U — none of which would surface from testing each scenario once under a single set of conditions. Variation types are domain-general; scenarios are domain-specific. This scales.

The 4-Layer Evaluation Architecture

Catch blind spots before customers do
1

Progressive Autonomy Routing

Don't hand full autonomy. Route by confidence and stakes. High confidence + low stakes = agent decides. Edge cases = human-in-the-loop with agent in shadow mode.
How: Agent shadows human on edge cases. Human resolves. Agent learns which components drive correct resolution. Autonomy expands as eval coverage grows. This is hard work — no shortcut for high-stakes.
2

Deterministic Validation

Use rules-based checks to catch CoT ≠ output contradictions. Don't ask the model to catch its own inconsistencies.
Example: IF reasoning contains "enhanced due diligence" AND classification = "standard risk" THEN escalate

Simple if-then rules comparing trace to output. External perspective, not self-evaluation.
3

Continuous Flywheel

Bias toward false positives (flagging too much > missing real problems). Then run a two-loop process.
Loop A: Review every positive — true or false? Update eval rulebook to be smarter.
Loop B: Sample agent runs that were passed by LLM-as-judge. Find missed defects. Convert to new evals.

This flywheel is what separates high-performance systems from the rest.
4

Factorial Stress Testing

The gold standard. Take each scenario and systematically add controlled stressors to measure what drives agent behavior.
Stressor types (domain-general):
• Social pressure cue ("my boss said this is fine")
• Contradictory context
• Time pressure element
• Hedging qualifier
• Stakeholder minimizing severity

Not cheap. Not for every agent. But if stakes are high and you don't know your failure modes — do this.
