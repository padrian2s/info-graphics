The 5 shifts that matter

1
The paradigm shift: from instruction to token 60 years of deterministic computing replaced by purchased intelligence
▾

The unit of work is no longer an instruction a human writes for a machine to execute. It's a token—a unit of purchased intelligence. You describe outcomes, feed context, and buy enough inference to get results. The human's job shifts from writing logic to specifying outcomes and managing the intelligence budget.

Old paradigm

  • Unit of work = instruction (deterministic).
  • Human writes code, machine executes code.
  • Value = how cleverly the human sequences instructions.
  • Bottleneck = developer time & headcount.

New paradigm

  • Unit of work = token (purchased intelligence).
  • Human specifies outcome, machine figures out the steps.
  • Value = ability to convert tokens into economic outcomes.
  • Bottleneck = context engineering & token management.
Key insight: This is not a tools upgrade. It's a change in what computing is. Intelligence is now a purchasable input with a price curve and a consumption curve.
2
The numbers: token costs are real and exploding $85K/mo avg AI spend • Cursor's AWS spike • Anthropic's $2.66B AWS bill
▾

StrongDM CTO: 3-person team targets $1K/day in token spend, no handwritten code. Cursor's AWS cost spiked from $6M to $12M in one month. Anthropic spent $2.66B on AWS against $2.55B revenue. Average org spends $85K/month on AI (up 36% YoY). OpenAI planning $2K–$20K/month AI employee tiers.

Price curve (deflation)

  • Per-token inference costs falling 10x–200x/year.
  • GPT-4 equivalent: $20/M tokens (2022) → $0.40 today.
  • Claude 4.5 Sonnet at $3/M input tokens — heading to cents.

Consumption curve (explosion)

  • Avg org: $85K/mo on AI, up 36% YoY.
  • Share planning >$100K/mo doubled: 20% → 45%.
  • Enterprise LLM spend: $4.5M (2023) → $7M (2025) → $11M+ (2026).
Jevons' Paradox: when a resource gets cheaper, you use more not less. Steam engines got efficient → coal exploded. Cloud got cheaper → AWS bills went up. Token costs fall → consumption skyrockets.
3
Three developer tracks — and the exposed middle Orchestrator gets rich • Systems Builder highest ceiling • Domain Translator doesn't know they're a dev yet
▾

The role of developer is differentiating into three distinct tracks with different skills, compensation dynamics, and career trajectories. The "exposed middle"—competent application coders without deep systems or domain expertise—sees its value collapse at the same rate as token costs.

Track 1: The Orchestrator

  • Doesn't write code — specifies outcomes, manages agents.
  • Skills: system design, spec writing, quality evaluation, token economics.
  • "Factory managers of intelligence." Compensation correlates with token budgets.

Track 2: The Systems Builder

  • Builds infra orchestrators use: agent frameworks, eval pipelines, routing layers.
  • Deep technical — understands model behavior at a mechanical level.
  • Small volume, highest compensation ceiling. Leverage is company-wide.

Track 3: The Domain Translator

  • Combines technical fluency + deep domain expertise.
  • The dental specialist, construction scheduler, insurance analyst who can now BUILD.
  • Largest of the three tracks. "Doesn't even know they're a developer yet."

The Exposed Middle

  • Competent application coders without deep systems or domain expertise.
  • Value of generic code production → zero at same rate as token costs.
  • "Using AI to code" is not enough. You must pick a track.
Career test: can you manage agents at scale, build the systems they run on, or point intelligence at the right problem in a specific market? If none, you're in the exposed middle.
4
Organizational restructure: headcount → intelligence throughput 500 engineers writing code < 50 engineers managing agents • Klarna's 7-figure rev/employee
▾

Output is no longer limited by headcount but by the ability to convert token spend into business value. AI-native companies run 3–5x revenue per employee. Enterprise backlogs—projects never economically viable before—become gold mines when building costs collapse.

The leverage shift

  • 500 engineers writing code may produce less than 50 managing agents.
  • Key: better specs, eval frameworks, context engineering, higher token budget per engineer.
  • $10M ARR AI startup: ~15 people vs traditional SaaS ~60 people.

The backlog gold mine

  • Internal tool saving 200 hrs/yr but costing 2,000 hrs to build — now viable.
  • Integration unlocking new revenue but requiring 4 devs for 6 months — now viable.
  • Enterprises optimizing for output & quality beat those optimizing for headcount.
Klarna's lesson: disastrous initial AI rollout, rehired customer service staff, but still hit 7-figure revenue/employee. The rocky path still compounds.
5
Market split: generalized scale vs specialized precision $200/mo Claude Max aimed well > $20K/mo agent budget aimed poorly
▾

Not big vs small. Enterprises compete on token volume + horizontal platforms. Startups and solopreneurs win on specificity + distribution + domain expertise. Intelligence is a commodity — competitive advantage migrates to everything around the commodity: distribution, domain knowledge, trust.

Enterprise play

  • Compete on token volume, build horizontal platforms.
  • Run agents 24/7 on broad shared workflows.
  • Advantage compounds with model upgrades. Moat = capital + infrastructure.

Specialist play

  • Win on specificity — the sharp angle, the niche market.
  • $200/mo Claude Max aimed well creates more value than $20K/mo aimed poorly.
  • Moat = distribution + trust + domain knowledge. Minimum viable team → 1.
Jevons' applied to TAM: cheaper intelligence makes more niche problems economically viable. The addressable market for software is expanding explosively. Vertical AI companies have opportunities in niches that weren't possible 6 months ago.

What to do with this (one-page checklist)

Pick the row that matches you

If you're an individual developer

  • Stop assuming "AI-assisted coding" is enough — pick a track: orchestrator, systems builder, or domain translator.
  • Build evaluation skills: can you judge whether AI output meets spec? That's the core of orchestration.
  • If you have domain expertise, lean into it hard — cheaper intelligence makes more niche problems viable to solve.
  • If you're deep in systems, learn model behavior at a mechanical level: context windows, routing, probabilistic reliability.

If you're an enterprise / team lead

  • Treat token spend as a lever to maximize ROI, not a cost to minimize. Route the right model to the right task at the right price.
  • Restructure around intelligence throughput: 50 engineers managing agents > 500 writing code by hand (with proper specs + evals).
  • Mine your backlog — projects that were never economically viable before are now gold when building costs collapse.
  • Build token management as a core competency: one supplier pricing change shouldn't create a crisis (see: Cursor).
Meta-lesson: the unit of work changed from instruction to token. Your career, your company, and your product must be positioned for a world where intelligence is a purchasable commodity that gets cheaper every quarter. The question is not whether you can afford tokens — it's whether you can aim them.
