    3) The Boba Game Simulator: delays → overreaction → bullwhip

    A simplified supply chain (Retailer → Wholesaler → Distributor → Factory). You can create a demand spike and watch inventory & backlog oscillate. The point isn’t precise prediction — it’s intuition: long delays amplify signals.
    Interactive
    Model notes: weekly steps; each tier targets an inventory level; orders propagate with delay; production has delay; stockouts incur backlog. This mirrors how “compute shortage” discussions can ignore upstream amplification.
    Try: set delay high and spike moderate. You’ll see bigger overshoots (gluts) *after* shortages. That’s the core “semiconductors are hard” intuition: even small demand shocks can become violent upstream.

    4) Bullwhip amplification (from consumer → semis → equipment)

    The narrative cites historical U.S. electronics consumption volatility, then shows how semiconductor and equipment swings can be much larger — especially with long lead times.
    Amplification
    Intuition: upstream tiers act like “gain stages” in an audio system — noise becomes feedback. Long lead times force forecasts; forecasts + incentives create over-ordering; corrections cause gluts.

      Commentary: what this argument is trying to change in your mental model

      Not a “defense of a company,” but a systems reminder: industrial scaling is not a software deploy. The critique targets shallow blame and short feedback loops in tech discourse.
      Interpretation
      • 1) “TSMC is the limiter” is often shorthand for “I don’t see the hidden constraints.”
        The essay reframes “shortages” as normal for semiconductors (and equally normal: gluts). When the system turns, it turns slowly — but it can overshoot violently.
      • 2) Competition helps long-term health, but it doesn’t magically erase near-term shortages.
        Even with more foundries, the suppliers are shared (EUV, deposition niches, materials, HBM). Scaling “everyone” simultaneously can still slam the same upstream nodes.
      • 3) The last mile matters: chips can exist while deployable systems lag.
        The narrative cites packaging/yield issues and rack/cooling integration delays. That creates weird phases where inventory exists but “usable compute” doesn’t.
      • 4) The software world has lost industrial intuition.
        The closing thesis is cultural: many “AI people” don’t understand how hardware gets made, so they talk about fabs like they’re Kubernetes clusters. The request is: patience + realism.
      • 5) A hidden subtext: capital allocation is constrained by uncertainty.
        Foundries don’t just scale because hype exists — they scale when demand is durable and monetizable. If the “AI ROI” is unclear, overbuilding becomes existential (depreciation + low utilization).
      How to use this as a builder / operator:
      If you’re planning AI capacity, treat the stack like a multi-year program: power, cooling, racks, networking, HBM, packaging, tools, then chips. Over-index on supply chain lead times the way you’d over-index on latency budgets in distributed systems.
