Anatomy of a Skill

What works, what breaks

The File Structure

# skill.md — the only required file

---
name: Competitive Analysis
description: Generates a structured competitive landscape report when user says "analyze our competitors" or "who are the players in [market]". Produces a markdown table with positioning, strengths, weaknesses, and strategic gaps.
---

# Methodology
## Reasoning & Frameworks
When analyzing competitors, evaluate on...

## Output Format
Produce a markdown table with columns...

## Edge Cases
If fewer than 3 competitors found...

## Example
[See examples/sample-output.md]

The 80/20 Rule for Skills

80% — Description (triggers correctly) 20% — Methodology (reasons correctly)
The methodology body needs 5 things:
1.Reasoning, not just steps — frameworks, quality criteria, decision principles
2.Specified output format — markdown? Excel? Exact fields/sections?
3.Explicit edge cases — everything a human handles via "common sense"
4.Example output — so the LLM knows what "good" looks like
5.Keep it lean — under 100–150 lines. Short + reliable > long + conflicting
Critical gotcha: The description MUST stay on a single line. If a code formatter breaks it across lines, Claude won't read past line 1. Skills will silently fail to trigger.

The Description Is Where Skills Go to Die

Bad — Vague, Passive
"Helps with competitive analysis"
"Useful for financial work"
"Assists with writing tasks"

Too diffuse to match. Triggers on everything tangential. Tells the LLM nothing useful.
Good — Specific, Pushy
"Generates a structured competitive landscape report when user says 'analyze our competitors' or 'who are the players in [market]'. Produces markdown table with positioning, strengths, weaknesses, and strategic gaps."

Names artifact types, includes trigger phrases, states output format. Anthropic says: make skills pushy so the LLM is confident to use them.

Agent-First Skill Design

The primary caller is now an agent, not a human
🔌

Description = Routing Signal

Not a label — a routing signal. Wording must match the outcome the agent has been given to look for in its goal. The agent reads the description to decide: "Is this the right skill for what I'm trying to accomplish?"

📜

Output = Contract

Frame like an API contract: what this skill gives you, what it doesn't, controllable fields, and what it enables. A declarative agreement the agent can confidently discover and act on.

🔗

Composability First

Don't design skills as endpoints. Design outputs that hand off cleanly to the next agent or sub-agent in the chain. Think end-to-end — if the output breaks the handoff, the whole pipeline breaks.

⚙

Hardwire When Needed

Skills are plain English — agents will often follow them, not always. If you need guaranteed behavior, use deterministic scripts. Knowing when to go deterministic is a sign of AI fluency, not weakness.

Agent-callable skills demand quantitative testing. In the past, humans could correct drift mid-conversation. Now, an agent uses the skill with no recovery loop — failure can be very expensive. You need a test suite: run a basket of tests, change the skill (like a version number), re-test. Skills trigger unpredictable parts of the transformer's latent space — you may need 3–4 wordings of "beautiful" to match your company's aesthetic, even with examples. Take the time. If you're producing 100 PowerPoints a week, getting it right saves everything.

The Three Tiers

How high-performing teams organize skills

TIER 1 Standard Skills

Consistent across the org. Brand voice, formatting rules, approved templates. Enterprise admins provision these widely. "Our brand voice is this. Everyone use it."

TIER 2 Methodology Skills

How your team performs high-value work predictably. Senior practitioners' craft — what takes a new hire months to learn. Client deliverable structure, deal memo format, analysis frameworks. This is where the alpha lives. Enterprise admins can't roll these out — they live in practitioners' heads and need to be extracted.

TIER 3 Personal Workflow Skills

Under-the-desk tools for your day-to-day. Don't keep these just on your laptop. When you're on vacation or sick, someone needs to run your process. Think systemically — actions and processes that skills can capture reliably.

How people are actually using skills

Real-World: 50K Lines of Operational Skills

A real estate GP built 50+ repositories of skills covering rent roll standardization, comps analysis, cash flow handling, and team handoff protocols. The agent runs operations — but the skills also serve as onboarding docs for new hires. The methodology doesn't live in someone's mind anymore. It lives in a repository.

Skills compound. Prompts don't.

People who've been building skills for 6 months have been refining and compounding — each iteration makes the output more predictable. People who've been prompting are still copy-pasting. Prompts are the basic 4x4 Lego block. Skills are the specialized pieces that build the castle. Prompts evaporate when the conversation ends. Skills are what persists.

Getting Started — By Level

Beginner
Find something you do 2–3x/week. Ask your AI to help you make a skill.md from your best conversations. Feed it what went well and what didn't. Iterate.
Intermediate
Think agent-readable. Are your handoffs clean? Are outputs structured as contracts? Is the description a routing signal? Test with a basket of scenarios.
Team / Enterprise
Tier your skills. Extract Tier 2 methodology from senior practitioners' heads. Version control everything. Build quantitative test suites for agent-callable skills.
