1
Anthropic killed PRDs — replaced them with "docs to demos" and 20 prototypes in 2 days Boris Cherny + Cat Wu, Claude Code team · verified via Lenny's Podcast + Coder.com
▾

Boris Cherny (creator/head of Claude Code) stated on Lenny's Podcast (Feb 2026) that the team operates with no sprints, no PRDs, and "everyone codes" — including the PM, designer, finance person, and data scientist. Cat Wu (founding PM) described the replacement: "docs to demos."

The "docs to demos" process

  • Step 1: Idea → working prototype (skip the spec/PRD entirely).
  • Step 2: Ship prototype to all employees immediately.
  • Step 3: Iterate based on "antfooding" (internal dogfooding).
  • Step 4: Prioritize: high usage + positive feedback → keep; low engagement → kill.
Source: Cat Wu, Coder.com interview; Aakash Gupta analysis

Verified numbers

  • 60-100 internal releases per day.
  • ~5 PRs/engineer/day (industry norm: 1-2).
  • ~20 prototypes in 2 days for a single feature (todo list).
  • 80%+ of Anthropic technical staff use Claude Code daily.
  • 90% of Claude Code's own codebase written by Claude Code.
Source: Boris Cherny, Lenny's Podcast Feb 2026; Pragmatic Engineer
Cherny quote: "By the end of the year, everyone is going to be a product manager, and everyone codes. The title 'software engineer' is going to be replaced by 'builder.'"
2
OpenAI ships on day one, hires only senior generalists, and uses the DRI model Evan Morikawa (Head of Applied) · verified via Pragmatic Engineer + LeadDev
▾

ChatGPT started from zero — fresh repo, fresh cluster, no legacy code. The team of ~130 engineers operates like a small startup. They hire only senior-and-above generalists who can work across mobile, frontend, and backend. Every project has one DRI (Directly Responsible Individual) with full decision-making authority.

How OpenAI plans

  • No traditional sprints. Quarterly planning assumes only 60-70% completion.
  • "Doing more than 70% probably means you weren't flexible enough."
  • PRDs are evolving: shorter, AI-enhanced, with dual metrics (user + AI quality).
  • Prototypes quickly become production — the line is intentionally blurred.
Source: Evan Morikawa, Pragmatic Engineer; Miqdad Jaffer PRD template

The DRI + startup model

  • DRI: one person owns the project end-to-end with full authority.
  • Small teams: most successful projects come from 2-3 people.
  • Extreme generalists: engineers work across the entire stack.
  • Research-engineering blur: researchers run A/B tests, engineers iterate on models.
Source: Pragmatic Engineer "Inside OpenAI"; Eng Leadership Newsletter
Morikawa philosophy: "It's easier to move faster when you have no baggage to carry." ChatGPT launched from a blank repo.

Both labs went agent-first: 100% AI-written code, fleets of parallel agents Boris Cherny + Sherwin Wu · verified via Fortune, Lenny's Podcast, OpenAI blog
▾

Boris Cherny hasn't manually edited a single line of code since November 2024 — 100% written by Claude Code. At OpenAI, Sherwin Wu's API platform team has 95% of engineers using Codex, managing 10-20 parallel agents each. Both labs independently arrived at "humans steer, agents execute."

Anthropic's agent-first approach

  • Boris ships 10-30 PRs per day — all AI-written.
  • Unlimited token allocation for teams.
  • "Strategic underfunding" — small teams + unlimited compute = efficiency.
  • Sid Bidasaria: "No formal processes. Super fluid. Prototype really quickly."
Source: Fortune Jan 2026; Boris Cherny, Lenny's Podcast

OpenAI's "harness engineering"

  • 3 engineers built 1M lines of code in 5 months — all via Codex agents.
  • ~1,500 PRs merged, averaging 3.5 PRs/engineer/day.
  • Code review dropped from 10-15 min to 2-3 min.
  • "Engineers are becoming sorcerers" — Sherwin Wu.
Source: OpenAI "Harness Engineering" blog; Sherwin Wu, Lenny's Podcast
10x gap: OpenAI reports that people not adopting agent-first approaches are 10x less productive — "whether you measure lines of code, commits, or business impact."
4
What traditional engineering practices both labs killed — and what replaced them Sprints, PRDs, code review rituals, role specialization — all gone
▾

Both labs converged on replacing traditional engineering rituals with speed-optimized alternatives. The pattern is consistent: remove process that predicts value, replace with process that demonstrates value. Working software beats documentation. Prototypes beat specifications.

What died

  • Sprints: replaced by continuous shipping (60-100 releases/day at Anthropic).
  • PRDs: replaced by prototypes at Anthropic; shorter AI-enhanced specs at OpenAI.
  • Role specialization: "everyone codes" at Anthropic; extreme generalists at OpenAI.
  • Manual code writing: 100% AI-written code for top engineers at both labs.
  • Lengthy code review: from 15 min to 2-3 min with AI assistance at OpenAI.

What replaced it

  • Rapid prototyping: 10-20 prototypes per feature, then internal dogfooding.
  • Antfooding / internal launch: ship to employees immediately, measure usage.
  • DRI ownership: one person owns end-to-end, no committee decisions.
  • Agent fleets: manage 10-20 parallel agents instead of writing code yourself.
  • Simplicity bias: "almost always pick the simplest possible option" — Cherny.
Caveat: Anthropic's "no PRDs" applies specifically to the Claude Code team's product feature development. Other Anthropic teams (safety, enterprise, core model) may still use more structured processes.
5
The convergence: both labs arrived at the same engineering philosophy independently Small teams + agent leverage + prototype-first + speed over process
▾

Despite different cultures (Anthropic: safety-first, measured; OpenAI: rapid progress, consumer-first), both labs independently converged on the same engineering philosophy. This suggests the pattern is a real solution, not just a cultural preference.

The shared pattern

  • Tiny teams, massive leverage: 2-3 people + agent fleets = what used to take 30+.
  • Prototypes over specs: demonstrated value replaces predicted value.
  • Speed as strategy: "optimize heavily for speed and velocity" (OpenAI).
  • Everyone builds: PM, designer, data scientist all write code.
  • Simplicity wins: delete code aggressively, avoid over-engineering.

Where they differ

  • Safety posture: Anthropic has Constitutional AI + RSP; OpenAI collaborates with AI Safety Institute.
  • Revenue model: Anthropic ($4.2B) projects break-even 2028; OpenAI ($13B) burning $9B.
  • Team size: Claude Code ~10 engineers; ChatGPT Applied ~130 engineers.
  • Agent tool: Anthropic = Claude Code; OpenAI = Codex.
  • PRDs: Anthropic killed them; OpenAI shortened + AI-enhanced them.
What this means for you: If both leading AI labs independently abandoned traditional engineering process, the signal is clear — the "builder" era is replacing the "software engineer" era. The practices that worked for the last 20 years are not the practices that will work for the next 5.

If you want to adopt Anthropic's model

  • Kill PRDs for feature development. Replace with "docs to demos": build a working prototype before writing any spec.
  • Ship internally first — get feedback from real usage, not meetings. Measure actual engagement.
  • Make everyone code. The PM, designer, and data scientist should all be building with AI tools.
  • Give teams unlimited token budgets but keep team sizes small ("strategic underfunding").

If you want to adopt OpenAI's model

  • Hire senior generalists who can own entire features end-to-end. Assign a DRI to every project.
  • Plan quarterly but assume 60-70% completion — anything more means you aren't flexible enough.
  • Adopt "harness engineering": have engineers managing fleets of 10-20 parallel agents, not writing code manually.
  • Blur the research-engineering line. Let researchers ship to production and engineers iterate on models.
Bottom line: Both labs agree on the core insight — prototypes beat specs, small teams + agent leverage beat large teams + process, and the "builder" role is replacing the "software engineer" role. The question isn't whether this transition happens. It's whether you lead it or get caught by it.
